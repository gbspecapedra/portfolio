## Production cutover

1. In the Vercel **portfolio** project, open **Settings → Environment Variables**. Confirm that `PRISMIC_REPOSITORY_NAME` and the sensitive `PRISMIC_WEBHOOK_SECRET` are scoped to **Production** and **Preview**. Keep **Automatically expose System Environment Variables** enabled so the app reads `VERCEL_ENV`. A project member with environment-variable access can verify the scopes.
2. After the authorized Production release, confirm in **Deployments** that the production domain points at the Prismic-enabled build. Check the homepage, all four case studies and `/sitemap.xml`. The no-input preview GET should return 400, the exit-preview GET 200, the revalidation GET 405, and a revalidation POST with an empty JSON object 401.
3. In Prismic **Settings → Webhooks**, a repository administrator should edit the existing **Portfolio — Next.js Revalidation** entry. Change the URL to `https://giselepecapedra.com/api/revalidate`, retain the existing secret and verify that only **A page is published** and **A page is unpublished** are selected. Enable the entry after the endpoint passes the checks above. Prismic sends the shared secret in the JSON body.
4. Use **Trigger it** in the Prismic webhook dashboard and check **Logs** for 200. A test event returns `{"revalidated":false}`. For an end-to-end check, publish a harmless update to an approved test document, then confirm the expected page and sitemap. Restore the test document afterward. [Prismic webhooks](https://prismic.io/docs/webhooks)

## Full-site draft previews

In Prismic **Settings → Previews**, confirm one entry for the Production URL and one for the stable protected Vercel Preview URL in the table. A repository administrator manages these settings. For the branch Preview, first sign into that Vercel host with an account that has project access. From the Prismic Page Builder, open an unpublished revision through the matching host. Confirm the document URL resolves correctly, navigate away and back, and use the toolbar’s exit control. A fresh session should show only published content. When the callback includes only a session ID, it loads the Prismic toolbar so the browser can receive the ref and retry the callback for the requested document. The app validates the ref with Prismic before enabling Next.js Draft Mode. Preview requests bypass fetch caching and use host-scoped cookies. The draft stays out of the published sitemap. [Prismic full-site previews](https://prismic.io/docs/previews) and [Next.js Draft Mode](https://nextjs.org/docs/app/api-reference/functions/draft-mode)

If the branch is retired, replace its Prismic preview entry with the stable alias of the active editorial branch. Keep Vercel Authentication enabled. Should Preview ever require immediate webhook delivery, target the stable alias and use Vercel **Protection Bypass for Automation** through Prismic’s private custom header `x-vercel-protection-bypass`, in addition to the independent Prismic webhook secret. A project automation bypass credential can grant access beyond this endpoint. Using time-based revalidation avoids issuing that credential or granting a deployment-wide exception. [Vercel Authentication](https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication) and [Protection Bypass for Automation](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/protection-bypass-automation)

## Cache and diagnostics

- A valid document event immediately expires the relevant Next.js tag. The homepage, case studies, shared settings and published sitemap use the same repository tag in each environment. The webhook clears its process-local project index. Other instances refresh their index within 15 seconds.
- Production uses the `prismic` tag and hourly time-based fallback. Preview uses the `prismic-preview` tag and 60-second time-based revalidation on the next request. The first request after the interval can serve stale content while refreshing. Vercel isolates its Data Cache by environment and scopes App Router tag revalidation to the same environment. [Vercel Data Cache](https://vercel.com/docs/runtime-cache/data-cache) and [Vercel ISR](https://vercel.com/docs/incremental-static-regeneration#on-demand-revalidation-limits)
- Vercel Authentication returns its own 401 or browser login response before the app. Application JSON `{"error":"Unauthorized."}` means the request reached the webhook and failed its secret or repository check.
- A 404 on a webhook POST calls for checking the deployment, host and exact `/api/revalidate` path. A GET returning 405 confirms the handler exists and uses POST. A POST returning 503 means the deployed secret is missing. A signed 400 indicates a malformed or unsupported event. A 500 indicates a revalidation failure and logs a generic diagnostic.
- If a draft URL is missing, check the Preview registration, Vercel access and the document UID. Reopen an expired preview from Prismic. The start route rejects invalid refs without setting Draft Mode and sends a no-referrer response. `/api/exit-preview` clears the session.
- In Draft Mode, a case study can render before its title and subtitle are complete. Fill in both fields before publication.
